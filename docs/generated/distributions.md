## What Each Package Owns

- **`hyperflux-next-dkms` (Core):** HyperFlux receiver kernel driver sources for DKMS.
- **`hyperflux-next-linux` (Core):** HyperFlux receiver driver, bridge, SDK, CLI, and base services.
- **`hyperflux-next-openrazer-driver-dkms` (Full):** OpenRazer kernel driver sources with the HyperFlux native transport, for DKMS.
- **`hyperflux-next-full` (Full):** Core plus the OpenRazer compatibility transport and OpenRGB integration for optional stock applications.
- OpenRazer's service and Python client, Polychromatic, and OpenRGB are optional suggestions, never package payloads. They stay packaged by the distribution.

## Install And First Run

- Package hooks create system users/directories and reload systemd and udev registration only.
- Installation does not start, stop, restart, enable, disable, or probe services or hardware.
- Removal does not stop or disable services either. A running bridge keeps running until the computer restarts, so turn the services off before removing the packages: `sudo systemctl disable --now hyperflux-next-bridge.service "hyperflux-next-client@$(id -u).socket"`.
- First run enables the units without starting them, then reboots with the receiver connected: `sudo systemctl enable hyperflux-next-bridge.service "hyperflux-next-client@$(id -u).socket"`, then `sudo reboot`.
- Live activation without a reboot requires disconnecting the receiver, so it is only for systems with verified alternate input: `sudo /usr/lib/hyperflux-next/hyperflux-next-activate activate-disconnected-driver`.
- Bridge restoration ships disabled in this package release.

### Core and Full on Ubuntu

Core is `hyperflux-next-linux`. Full is `hyperflux-next-full`: Core plus the OpenRazer compatibility transport, so stock OpenRazer applications can use your devices too.

- `hyperflux-next-openrazer-driver-dkms` replaces the OpenRazer driver package of Ubuntu (`openrazer-driver-dkms`, `openrazer-kernel-modules-dkms`) and stands in for it, so the stock OpenRazer service still installs.
- Ubuntu 26.10 packages OpenRazer 3.12.4 as `openrazer-daemon`.
- Optional stock applications: `openrazer-daemon` (Stock OpenRazer service for compatible application access), `python3-openrazer` (Official Python OpenRazer client API).
- To use the stock OpenRazer service, add yourself to the `openrazer` group, then log out and back in: `sudo gpasswd -a "$USER" openrazer`.

**Full on Ubuntu has no OpenRGB plugin.** That is a limit of what Ubuntu 26.10 packages, not of HyperFlux: Ubuntu 26.10 packages a development snapshot of OpenRGB from before 1.0, which loads plugins built for plugin interface 4 only. The HyperFlux plugin is built for plugin interface 5, which OpenRGB 1.0 final and 1.1 use, and OpenRGB refuses a plugin built for another interface. Doctor reports Full as ready without it. Arch Linux packages OpenRGB 1.1 and Debian 14 packages OpenRGB 1.0 final, so Full there includes the plugin. When Ubuntu packages OpenRGB 1.0 final or newer, its Full packages can include the plugin.

- Package scripts mirror the Arch hooks: they create the system user and directories and reload systemd and udev. They never enable, start or stop a service.
- `hyperflux-next-dkms` and the Full OpenRazer driver package hand their driver sources to DKMS when they are installed and remove every built copy when they are removed.
- Programs must run on the glibc 2.44 that Ubuntu 26.10 ships.

### Secure Boot on Ubuntu

If Secure Boot is on, Linux only loads drivers signed by a key it trusts. DKMS on Ubuntu signs the HyperFlux driver with a key made on your computer, so you need to tell the computer to trust that key once.

1. Check whether Secure Boot is on:

   ```sh
   mokutil --sb-state
   ```

   If it says `SecureBoot disabled`, you can stop here.

2. Ask to trust the key. Choose a one-time password when asked; you need it after the restart:

   ```sh
   sudo update-secureboot-policy --enroll-key
   ```

   If that command says there is no key to enroll, run this instead:

   ```sh
   sudo mokutil --import /var/lib/shim-signed/mok/MOK.der
   ```

3. Restart the computer. A blue MokManager screen appears. Choose **Enroll MOK**, then **Continue**, then **Yes**, type the password, and reboot.

4. Check that the driver is signed:

   ```sh
   modinfo -F signer hid_hyperflux_next
   ```

   It prints the name of the key. An empty line means the driver is not signed.

### Remove HyperFlux Next on Ubuntu

Removing the packages does not stop the HyperFlux services, so turn them off first.

1. Turn off the HyperFlux services:

   ```sh
   sudo systemctl disable --now hyperflux-next-bridge.service "hyperflux-next-client@$(id -u).socket"
   ```

2. Remove the packages:

   ```sh
   sudo apt remove hyperflux-next-dkms hyperflux-next-linux hyperflux-next-openrazer-driver-dkms hyperflux-next-full
   ```

   This also removes every built copy of the driver from DKMS.
