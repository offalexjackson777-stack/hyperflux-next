## OpenRazer Driver And Updates

`hyperflux-next-openrazer-driver-dkms` owns the source-bound patched driver at `/usr/src/openrazer-driver-3.12.4`. It provides `openrazer-driver-dkms=3.12.4` and `hyperflux-openrazer-driver-abi=3.12.4` and conflicts with `openrazer-driver-dkms`, so a system update cannot install a second owner over the transformed source tree.

Official OpenRazer `3.12.4` daemon and Python-client packaging may receive distribution release-suffix updates. Runtime readiness is checked with the transformed module capability `hyperflux_native_transport=razer-feature-report-v1`, not a package release string. A different upstream source version fails closed and keeps `hyperflux-next-openrazer-relay.service` stopped until HyperFlux is rebased and reverified.

## Turning It On And Rolling Back

Installation leaves every HyperFlux service disabled and inactive. Keep the receiver connected, enable the units without starting them, and reboot:

```sh
sudo systemctl enable hyperflux-next-bridge.service "hyperflux-next-client@$(id -u).socket"
sudo reboot
```

After login, run the read-only `hyperfluxctl doctor`; the read-only `hyperfluxctl qualification --json` report is what a hardware report asks for. Live activation without a reboot requires disconnecting the receiver, so use `sudo /usr/lib/hyperflux-next/hyperflux-next-activate activate-disconnected-driver` only when another keyboard, mouse, or verified SSH session can recover the machine.

Rollback uses a complete prior source-bound Core/Full pair through the package manager. Do not copy files into `/usr/src`, overwrite DKMS trees, or mix an upstream OpenRazer driver package with the HyperFlux-owned transform. Existing configuration remains preserved across supported package transitions.

The Arch package base consumes independently staged `linux` and payload-bearing `full` components. Ubuntu 26.10 and Debian 14 `.deb` packages and Fedora 44 and openSUSE Tumbleweed `.rpm` packages of both editions are built and tested automatically every week and published in the signed package repository, but not yet confirmed on real hardware.
